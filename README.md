### 1. GOAL ― 本プレゼンで得てほしいもの

Kubernetes やブロックチェーンはバズワード先行になりがちです。本資料では **「どんな案件が生まれ得るか」** を非エンジニアの皆さまが具体的に想像できる状態をゴールとします。

### 2. WHY ― 今、トレーサビリティが急務な理由

| 課題                  | インパクト            |
| ------------------- | ---------------- |
| **政府ガイドライン・義務化強化**  | 対応遅延 = 法的リスク拡大   |
| **リコール/品質事故コストの高騰** | 自動車業界で 1 件数十億円規模 |

#### ターゲット（誰が一番困っているか）

* 政府・省庁 SDG対応の一環
* **大企業 × 自社工場保有** …法規制の影響範囲が広く、納入責任が重い
* 投資余力があり ROI を回収可能
* ※ スタートアップは EKS など基盤コストが負担になりやすい

---

### 3. WHAT ― 解決策のキモ

#### 3‑1. パッケージ全体像

**トレーサビリティ + Kubernetes + プライベート・ブロックチェーン** をワンパッケージで提供。

| 要素                                | 役割                | もたらす価値                |
| --------------------------------- | ----------------- | --------------------- |
| **Kubernetes**                    | サーバーの自動配置・自己修復    | 24h/365d 安定稼働、運用コスト削減 |
| **プライベートBC** (Hyperledger Fabric) | 改ざん不可の共有台帳        | 不正リスク最小化、監査対応容易       |
| **シナジー**                          | k8s が BC ノードを自動管理 | 多社・高頻度更新でも低コスト        |

#### 3‑2. 技術をかみ砕く “たとえ話”

* **Kubernetes** = Google製のコンテナ技術最高峰。*24 時間働く“工場長ロボ”* …箱（コンテナ）を自動で配置・増減し、サーバーダウン時も理想台数へ自己復旧。
* **プライベート・ブロックチェーン** = *改ざん不可の“共有ノート”* …取引・検査・出荷履歴を証明付きで保存し、監査＆ブランド価値を強化。

#### 3‑3. ビジネスモデルの横展開

1. **自動車部品** で PoC → 実績獲得
2. **化学薬品** へ横展開（参画社数アップ）
3. **半導体** 等 高精度産業へ拡大
   → **業界コードを差し替えるだけ** の継続収益モデル

---

### 4. HOW ― 導入ステップと市場動向

1. **政府・省庁要請** で各大手 SIer がモジュール開発を受託。
2. **初期リリースの課題**：機能不足 & AWS コスト高騰 → リファクタリング案件が発生。
3. **研究開発チーム** へスケールアップし、継続的な最適化と追加機能開発を実施。
4. **他 SIer へ波及** …同規模対応が進行中、市場全体で需要拡大。
